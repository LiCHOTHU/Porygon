# Jigglypuff four-condition comparison

## Frozen protocol

1. **Base FM:** existing `runs/jigglypuff/best.pt`, original epoch 17. No retraining.
2. **BC refinement:** initialize from that base; train on exactly 30 supplementary
   demonstrations, selected once with NumPy seed 42. Original eight held-out
   demonstrations supply offline validation. No original training demos are added.
3. **DICE-RL:** original frozen base plus a new zero-initialized residual and critic;
   offline training on those same 30 demos plus all 18 saved reviewed evaluations.
4. **DICE-RL + CAST:** same base, replay, critic configuration, batch-index schedule,
   seed and optimizer budget; replace the actor loss with Porygon's CAST field loss.

The 18 evaluations contain 11 operator-labeled successes and seven failures.
`.pending` takes are excluded. Supplementary demonstration success is assumed
from the user-designated expert set, not independently inferred from video.
The selected IDs, labels, behavior checkpoint, exclusions and base checksum are
frozen in `runs/jigglypuff_four_way/experiment.json`.

**Provenance matters:** these recorded evaluations were generated by the stronger
`jigglypuff_continued/best.pt`, not by the original base. This is an **offline**
common-dataset comparison, not matched-budget on-policy robot fine-tuning.
The actor/critic runs do not interact with the robot. Do not populate paper
success-rate cells with their training losses or offline action errors.

## Replay and model adaptation

- Frozen visual/proprioception features come from the original base encoder.
- Policy rollouts use `follower_joint.csv` for state and `policy_commands.csv`
  for actions, never the stationary leader as policy-action ground truth.
- Expert trajectories use leader joint positions as demonstration targets.
- Each transition groups eight actually logged commands. The last full window
  may overlap its predecessor so terminal labels are retained without invented
  padded control commands. No transition crosses episode boundaries.
- The FM generator retains its original 30-step noise/action representation.
  The critic reads only the eight-action executed prefix. Residual corrections
  are masked to that prefix. Unexecuted suffix values have zero critic influence.
- The original FM normalization and prompt are retained in all conditions.
  BC keeps the original normalized-target/output clipping; DICE's residual sum
  is unbounded internally, as in the repository's standard DICE configuration.
- The critic is noise-independent because behavior latent samples were not saved.
  Newly sampled actor particles still pair base and residual with the SAME full
  latent noise. The initial zero residual exactly recovers the original base.
- Operator-adjudicated attempt endings are treated as terminal, including failed
  time-limit attempts. Only the terminal transition receives success reward 1;
  failures receive 0. Discounting uses elapsed command time in nominal 15 Hz steps.
- Legacy videos have no per-frame timestamps. End-anchored image/state alignment
  remains approximate; macro-action inference boundaries were also not logged.
  These limitations must be disclosed for this dataset and improved for future
  collection before claiming exact command-time observation alignment.

## Training and checkpoint selection

BC runs 40 additional epochs at peak LR 3e-5. The fixed-budget fine-tuned endpoint
is `bc_refinement/final.pt` (copy of `latest.pt`). Its `best.pt` may instead remain
the original checkpoint when held-out imitation error does not improve; that
incumbent is NOT presented as a newly fine-tuned model.

Both RL runs use 6,000 critic updates, 500 critic-only warmup updates, actor updates
every two steps, batch 32, equal expert/rollout sampling, 16 actor noise samples,
five critics and 256×256 hidden layers. Actor/critic LRs are 1e-4, Polyak coefficient
0.01, discount 0.99, and a shared CQL-style penalty weight 0.1. The DICE actor uses
the repository's standard residual/Q-filtered BC objective (BC weight 100). CAST
uses `field_pointwise`, gradient reward source, Q step 1, weak base restoration
0.05, dead-zone restoration 1, radius 0.05 RMS, Q-field cap 1 and total cap 0.15.

Core losses are reused from `imitation/algos/dice/distill_rl.py` and
`drift_field.py`; real-robot prefix adapters are in `residual_policy.py`.
These are task-specific offline settings, not a claim to reproduce every
published online DICE-RL hyperparameter. Only the actor update differs between
the two RL runs. Both keep the original base and encoder frozen.

## Completed first-seed run

BC completed 40 additional epochs; DICE-RL and CAST each completed 6,000 updates,
sequentially. All three final checkpoints passed CUDA loading and sampling in
Docker. The base checkpoint was reused, not retrained.

On the same 1,038 held-out original-data samples, fixed-noise normalized MSE for
the first eight actions was:

| Condition | Offline prefix action MSE (lower is better) |
|---|---:|
| Original base FM | 0.05276 |
| BC refinement, final epoch 40 | 0.07927 |
| DICE-RL, update 6,000 | 0.05309 |
| DICE-RL + CAST, update 6,000 | 0.05686 |

These measure agreement with demonstrations, not real-robot success. RL is
optimizing labeled reward rather than reproducing held-out actions, so this
table neither establishes an RL success improvement nor a success-rate ranking.
`offline_comparison.json` also includes per-joint and gripper MAE.

The checkpoints are available inside the current Docker container at
`/porygon/real_robot/runs/jigglypuff_four_way/<bc_refinement|dice_rl|cast>/final.pt`.
Use `/porygon/real_robot/runs/jigglypuff/best.pt` for the original base condition.
The GUI loader supports all four and identifies RL mode/update in its status.

Each RL run writes `latest.pt` every 500 updates and `final.pt` at the fixed
budget. These files are not selected by unverified Q-value or robot success.
`evaluate_comparison.py` compares all four endpoints using the same held-out
eight-step action metric. Real-robot success rates require separate GUI trials.

## Sequential execution

The original base is reused, then BC refinement completes, then the supervisor
runs DICE-RL followed by CAST. It stops the queue if a stage fails. No two
refinement training stages run concurrently.

Progress is under `real_robot/runs/jigglypuff_four_way/`:
- `pipeline_status.json`, `pipeline.pid`, `pipeline.log`
- `bc_refinement/status.json`, `dice_rl/status.json`, `cast/status.json`
- Per-stage `train.log`, `metrics.jsonl`, and checkpoint files
- `replay_report.json`, `audit.json`, and final `offline_comparison.json`

The inference wrapper supports `policy_type=offline_residual` and needs only the
base plus residual actor at deployment, not the critic. It returns the full
30-step base chunk with corrections on the nominal first eight steps. The GUI
locks the execution horizon to eight, retaining its common latency-compensation
behavior. If that compensation skips into the suffix, suffix predictions remain
the frozen base's actions. This is another reason to distinguish nominal chunks
from logged executed-command windows in the legacy replay. Current Docker copies must be
updated with the corresponding Porygon modules/checkpoints before selecting them.
